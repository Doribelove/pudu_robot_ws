## 1. 当前唯一目标

在静态栅格地图上实现一套稳定的分层 A2B 全局规划器，并在不同规模地图上验证：

1. 相对全图二维搜索是否降低规划耗时、CPU 和内存；
2. 是否生成无静态碰撞、运动学可行的全局参考路径；
3. 路径长度、净空、曲率、连续性和通行偏好是否可接受；
4. 拓扑失败、走廊失败、运动学修复失败和全图回退是否可观测、可复现。

本课题当前不再以“四种独立算法谁更好”为研究问题。已有四算法实验目录和报告只作为历史材料保留，不删除、不覆盖、不继续扩展为正式主结论。

## 2. 选定的正式架构

```text
静态地图 + 起点终点 + 车体 footprint
                    ↓
L1：二维骨架拓扑图 + 图 A*
                    ↓
L2：走廊内二维栅格 A*
     失败时扩大走廊，必要时全图回退
                    ↓
几何路径检查
                    ↓
L3：局部 Hybrid A*
     只修复急转弯、窄通道和拼接违规窗口
                    ↓
最终静态碰撞与运动学验收
                    ↓
有效路径 / 结构化失败原因码
```

### 2.1 L1：二维骨架拓扑图 + 图 A*

正式主线固定使用当前已经实现的 `skeleton_distance_transform_v1`：

```text
静态 footprint 障碍膨胀
→ 自由空间距离变换
→ 自由空间骨架化
→ 骨架节点和边压缩
→ 图 A* 选择通道
```

L1 只使用二维几何状态，不引入全图 yaw，不进行车辆运动原语搜索。

L1 输出至少包括：

- 拓扑节点序列；
- 拓扑边序列；
- 走廊中心线或走廊区域；
- 通道宽度和最小净空；
- 拓扑路径长度；
- 拓扑预计算耗时、CPU、峰值内存和文件大小；
- 拓扑失败原因码。

Voronoi、其他骨架提取方式和多分辨率地图目前不属于主线实现。除非现有方案经过验证确实无法完成任务，否则不得为了增加方案数量而实现这些分支。

### 2.2 L2：走廊二维栅格 A*

L2 正式主算法固定为二维栅格 A*，状态为 `(x, y)`，不携带 yaw。

L2 负责：

- 在 L1 走廊内进行几何路径搜索；
- 走廊失败后的逐级扩大；
- 必要时执行全图二维 A* 回退；
- 输出路径、搜索节点数、搜索空间比例、耗时和失败原因。

所有请求必须使用同一套降级顺序：

```text
拓扑走廊
→ 扩大走廊
→ 全图二维 A*
→ 进入局部运动学修复
→ 返回结构化失败码
```

走廊宽度、扩大级别、超时和回退条件必须写入 protocol，不得按 query 临时调整。

RRT* 不是当前正式 L2 主线。已有 RRT* reference/surrogate 结果不得作为正式结论；除非后续明确批准并接入成熟、独立、可复现的实现，否则不新增 RRT* 评测。

### 2.3 L3：局部 Hybrid A*

L3 只在 L2 路径出现以下情况时触发：

- 起点或终点连接困难；
- 急转弯或曲率超限；
- 航向不连续；
- 窄通道中的局部不可行段；
- L2 分段拼接不连续。

L3 默认使用局部 Hybrid A*，不对整张超大地图进行全程运动学搜索。

L3 输出的修复结果必须与 L2 前缀和后缀拼接，并重新执行：

- 完整 footprint 静态碰撞检查；
- 曲率和最小转弯半径检查；
- 航向连续性检查；
- 位置连续性检查；
- 起终点误差检查。

Kinodynamic-RRT 仅保留为后续困难窗口扩展接口。当前不使用未验证的 surrogate 后端伪造成功，也不允许多个算法共用一个隐藏的路径生成器。

## 3. 车辆约束和环境边界

具体车辆运动学协议、footprint、地图分辨率、动态障碍开关、超时和碰撞语义以当前 `AGENTS.md` 及正式 protocol 为准。任何 Codex 执行前必须先读取该文件，不得从历史聊天内容猜测或自行修改约束。

所有正式运行必须遵守：

- 只使用静态栅格地图；
- `dynamic_obstacles=false`；
- 固定地图、固定 query、固定 footprint 和固定随机种子；
- 不做动态重规划、局部速度控制、Gazebo 行驶时间、建图、定位或多机调度；
- 不新增多分辨率地图或地图金字塔；
- L1、L2 不引入全图 yaw 状态；
- L3 失败必须返回结构化原因码，不能用原地旋转、倒车或空路径伪造成功。

如果本文件与 `AGENTS.md` 的具体参数发生冲突，必须先停止正式实验并报告冲突，不得静默选择一个版本。

## 4. 统一接口和数据流

### 4.1 输入

- 地图 YAML/栅格图及其 hash；
- 起点和目标位姿；
- 车体 footprint 和运动学参数；
- 静态通行偏好配置；
- protocol 版本和随机种子。

### 4.2 中间结果

L1：

```text
topology_nodes
topology_edges
corridor_geometry
corridor_width
minimum_clearance
```

L2：

```text
grid_path_xy
expanded_nodes
generated_nodes
search_space_ratio
grid_mode
fallback_attempts
```

L3：

```text
repair_windows
repair_attempts
repair_success
repair_time
splice_position_error
splice_yaw_error
```

### 4.3 输出

最终输出必须包含：

- 全局参考路径及航向；
- `action_success`；
- `static_footprint_valid`；
- `kinematic_valid`；
- `final_valid_success`；
- 路径分段来源：`topology`、`grid`、`kinematic`；
- 失败原因码；
- 各层耗时、CPU、内存和回退记录；
- 路径质量指标。

`action_success` 不等于最终成功。只有通过静态和运动学验收的路径才能计入 `final_valid_success`。

## 5. 正式开发阶段

### P0：冻结输入和协议

- 读取并遵守 `AGENTS.md`；
- 冻结地图集、query 集、footprint、分辨率和 protocol；
- 校验所有起终点和地图 hash；
- 建立新的实验输出目录，不覆盖旧 Stage 3-8 或四算法目录。

### P1：统一分层接口

- 将 L1、L2、L3 串成一次端到端请求；
- 统一失败码和路径来源标记；
- 记录每层的 wall time、CPU、RSS/PSS 和节点数；
- 记录源码版本、代码 hash、地图 hash 和 query hash。

### P2：完成 L1 预计算和可视化

- 生成拓扑图并持久化；
- 验证地图和 footprint 变化时不会错误复用；
- 输出地图、骨架、节点、边和走廊叠加图；
- 统计拓扑构建时间、内存、节点、边、连通分量和文件大小。

### P3：完成 L2 走廊搜索和回退

- 实现走廊内二维 A*；
- 实现固定的走廊扩大策略；
- 实现全图二维 A* 回退；
- 确保所有层共享同一次请求的时间预算；
- 验证失败原因码和回退记录。

### P4：完成 L3 局部修复

- 实现违规窗口检测；
- 实现局部 Hybrid A*；
- 实现 L2 前缀、L3 修复段、L2 后缀拼接；
- 完成最终 footprint、曲率、航向和拼接验收；
- 修复失败时返回原因码，不降低硬约束伪造成功。

### P5：小规模 smoke gate

在最小正式地图和少量固定 query 上验证：

- L1 能正确构建和挂接；
- L2 能在走廊内搜索；
- L2 失败时能正确回退；
- L3 能修复至少一类真实违规窗口；
- 成功路径无静态碰撞和运动学违规；
- 所有失败都带可分类原因码。

smoke 未通过前，不得开始多地图正式性能实验。

### P6：不同规模地图正式评测

使用固定地图族和固定 query 集，在每张地图上评测同一套分层实现。正式统计至少包括：

- 规划成功率和最终有效率；
- 静态碰撞数和运动学不可行段数；
- 端到端耗时 P50/P95/P99；
- CPU 时间；
- 峰值 RSS/PSS；
- L1、L2、L3 分层耗时；
- 拓扑预计算及摊销成本；
- 回退和 L3 触发比例；
- 路径长度、净空、曲率、连续性和偏好指标。

### P7：报告和结论

结论只回答：

> 在静态超大栅格地图上，固定的 L1 拓扑 + L2 栅格 + 按需 L3 运动学组合，是否比全图二维 A* 更快、更省资源，同时保持可行性和可接受的路径质量。

## 6. 指标定义

### 6.1 可行性指标

- 静态 footprint 碰撞路径数；
- 运动学不可行段数；
- `final_valid_success`；
- L3 修复成功率；
- 拓扑误判率；
- 走廊失败率；
- 全图回退率；
- 失败原因码分布。

硬验收要求由 `AGENTS.md` 和 protocol 冻结，至少不能用有碰撞或运动学违规路径计为成功。

### 6.2 效率指标

- L1 构建 wall/CPU 时间；
- L1 峰值内存和持久化大小；
- 在线拓扑查询时间；
- L2 搜索时间和展开节点数；
- L3 修复时间和修复窗口大小；
- 端到端 wall time P50/P95/P99；
- CPU 时间和平均核占用；
- 峰值 RSS/PSS；
- 搜索空间比例；
- 拓扑预计算成本摊销后的总成本。

### 6.3 路径质量指标

- 路径长度；
- 相对全图二维 A* 的长度比；
- 最小净空及净空 P5/P50；
- 最大曲率和曲率 P95；
- 航向变化总量；
- 大转角数量；
- 航向连续性；
- L3 修复段长度占比；
- 修复引入的额外绕行比例；
- 横向偏好满足度；
- 路径分段来源比例。

## 7. 评测对照口径

主研究对象只有一套：

```text
L1 骨架拓扑 + L2 走廊栅格 A* + L3 局部 Hybrid A*
```

全图二维 A* 只作为效率和路径质量参照，用于量化：

- 搜索节点减少多少；
- 在线耗时是否降低；
- CPU 和内存是否降低；
- 路径是否明显绕远；
- L3 修复是否增加额外代价。

不再把 NavFn、Smac、A*、Hybrid A*、RRT*、Kinodynamic-RRT 组织成新的四算法排名。历史 V0/V1/V2 和四算法目录只用于说明背景、发现问题和保留可追溯性。
