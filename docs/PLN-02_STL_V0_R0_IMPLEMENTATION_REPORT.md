# STL-V0-r0 独立联合规划实现与验证 — 李永祺

2026-09-09。**STL-V0 独立主线已建立并可运行，过渡位置、朝向及时间参与优化。** 受控规则场景通过，真实地图物理预检 6/8；完整 R2 语义验收尚未实现，当前为离线研究原型。

## 1 建立独立架构

```mermaid
flowchart LR
  S[语义规则与时间要求] --> P[任务进度 × 可行区域]
  F[原始栅格 → 凸可行空间集合] --> P
  P --> R[候选路线枚举]
  R --> J[联合优化位置、切向与时间]
  J --> V[区域、曲率、规则及车体检查]
  V --> O[比较轨迹代价并选择]
```

目标：让路线选择考虑真实轨迹可行性。采用任务乘积图上的有界 Yen 枚举，逐候选用 SLSQP 优化三次 Bézier 曲线，最后比较通过检查的轨迹代价。

结果：独立包、入口、输出协议均已建立；没有调用 3D、2A、旧骨架或历史规划路径。仅共享原始地图与实验物理条件。其启发来自 [STL–GCS](https://arxiv.org/html/2605.23240v1)，**首版尚未实现论文的 GCS 凸松弛与完整 STL 编译，不具备全局最优或完备性保证**。

## 2 验证可优化的过渡位姿

![受控靠右场景实测](assets/stl_v0_r0/right_band.png)

目标：语义规则直接改变可行轨迹。采用车道段 `y ≤ −0.4 m` 半空间和朝向锥约束；相邻段共享位置、物理速度，朝向由优化后的速度方向确定。图中浅色框是原始区域盒，实际可行范围还受半空间限制。

结果：该场景过渡点相对初值最大移动 **0.640 m**，两处过渡朝向约 **−8.41° / +8.41°**；路径长 **8.104 m**。直行、转弯、靠右、禁区绕行并限时访问共 4 个正向场景通过；不可能的 0.1 s 访问时限案例未输出有效轨迹。失败状态表示本次求解未通过，不是求解器给出的全局无解证明。

## 3 在冻结真实地图上预检

![停车区到通道实测轨迹](assets/stl_v0_r0/real_pass.png)

目标：确认独立链路能在原始地图上生成车体可行轨迹。采用 0.05 m 栅格、完整 padded 矩形车体（半长/半宽 0.265/0.225 m）、最小转弯半径 0.40 m，仅前进；保守外接圆膨胀后生成凸矩形覆盖。

结果：原始 selected8 起终点保持冻结，**6/8 通过物理预检**。6 条轨迹均通过连续曲率界检查和独立矩形车体 SAT 碰撞复核；密集复核步长最大不足 0.0069 m、朝向步长不足 1°。静态硬约束被处理，原 R2 的靠右／停车偏好完整验收仍为“未评估”，不可把本表称作完整语义成功率。

| 原始查询 | 物理预检 | 路径长 m | 单次规划 s |
|---|---|---:|---:|
| cmp2-01-lane-north | 通过 | 54.71 | 0.602 |

规划时间包含构图、候选枚举和连续求解检查，不包含共享地图准备、覆盖生成、独立车体复核与绘图。这里是单次研究测量，既非冷启动同轮性能对比，也不是多地图结论。

## 4 保留失败证据与下一步

![停车区内部查询的覆盖失败](assets/stl_v0_r0/cover_failure.png)

目标：区分模型漏路和环境无路。采用原安全栅格连通性检查对照凸覆盖图；两组失败均显示安全栅格起终点仍连通，有限凸覆盖没有找到连接。

结果：`lane-to-parking`、`parking-internal` 明确记录 `NO_ROUTE_IN_FINITE_COVER`，未输出伪造路径或借旧架构回退。下一阶段优先改进覆盖连通性，再补原 R2 谓词与独立验收；候选枚举及非凸优化的漏解仍须继续评估。
