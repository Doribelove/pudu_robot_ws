# 3YD-V1 下一阶段建议：静态通行质量、失败恢复与动态更新

本计划基于已命名为 **3YD-V1** 的轻量 L1＋0.15 m L2 静态实验（含必要的 0.05 m L2 回退）。以下是下一阶段建议，新增能力尚未实现。当前 3YD-V1 及原始 3YD-V0-r0 保留为对照，新增代码和结果另行保存。

## 对当前结果的判断

可以进入下一阶段。已验证的是固定真实地图和查询集中的静态规划、精细回退和偏好传递；动态障碍、任意查询的路线恢复和执行切换仍需补齐。

| 观察 | 判断 |
| --- | --- |
| 三组均 60/60 成功；每组为 20 条查询各重复 3 次 | 保持了该固定集的最终静态成功率，没有证据说明成功率提高或已具备任意场景恢复能力 |
| 3YD-V1 中 42/60 次 L2 保持粗图、18/60 次完整精细回退 | 粗图直接完成率为 70%；最终 100% 成功包含回退的贡献，L3 始终使用精细图 |
| 被接收但独立检查不通过的轨迹为 0 | 当前样本满足既定几何与车辆检查，不能直接扩展为动态或实机执行结论 |
| 配对路径长度比中位数 0.9993，最大 1.0948 | 典型路线长度基本保持；两条停车区内部查询增加约 9.4%–9.5%，需要逐条解释和修复 |
| 靠右目标带占比 P50：91.1% → 91.9% | 整体接近基线；两条停车区查询的有效车道段两版均为 0%，一条路口转弯查询约 91.9% → 87.7%，不能只看中位数 |
| 首次查询 P50：15.417 → 4.606 秒 | 减少约 70.1%，粗栅格对首次搜索有效 |
| 重复查询 P50：4.425 → 1.597 秒 | 减少约 63.9%，接口与缓存改造也有明显作用 |
| 查询进程树峰值 RSS：3.608 → 2.714 GiB | 减少约 24.8%，全图与 L3 服务仍有固定开销 |
| 全部查询 P95：16.814 → 15.626 秒 | 只减少约 7.1%，长耗时仍是主要性能问题 |
| 6/20 条查询使用完整选定路线区域的 0.05 m L2 | 精细回退保住可达性，也保留了较高搜索成本 |
| 新组 L2 状态与几何最大值约 18.034 MiB，基线约 5.356 MiB | 通道变宽后，回退场景的局部状态内存上升；不能把总 RSS 下降解释为所有内存项都下降 |
| 软参考代价适配 P50 约 0.680 秒，Smac 搜索与平滑约 0.086 秒 | 重复查询应优先优化输入准备；当前证据不支持优先替换 Smac |

轻量 L1＋0.05 m L2 的首次查询 P50 为 15.768 秒，未见改善；重复查询为 1.932 秒。因此轻量静态链路与缓存主要解决了重复开销，降分辨率进一步解决了首次搜索。L1 构建与文件体积的大幅下降，还来自取消成对车辆轨迹的离线验证和存储，几何可行性延后确认。

三组各 60/60 次成功，代表 20 条不同查询各重复 3 次。偏好切换 54/54 次、窄通道 3/3 次、最终回归 51 项通过。新组与基线成对路径长度比中位数约 0.9993，但个别路径增加约 9.5%；后续必须继续报告路径质量。

## 工作包 1：停车区与路口质量诊断、局部精细连接及候选路线失败恢复

这是下一批最先建议实施的工作包。先确认可达性和路径质量，再评价减少完整精细重搜带来的时间收益，同时补齐轻量 L1 延后几何验证后的失败恢复。

1. 逐项定位六条停车区相关回退查询的断连原因，区分粗栅格保守聚合、端点落格、区域边界与车辆转弯约束。用三组配对轨迹追踪两条停车区内部查询的约 9.5% 绕行，以及路口和停车区有效车道段的偏好不足，判断问题来自 L1 路线、L2 参考还是 L3 软代价响应；两组轻量 L1 均出现停车区绕行，不能只归因于 0.15 m。
2. 对可局部解决的断连，在明确边界的 0.05 m 区域内生成精细连接，再接回粗图参考路。记录局部区域大小、连接方向、地图版本和总耗时；必要时保留原有完整精细回退。
3. 某条候选路线经精细检查仍不可行时，让 L1 尝试其他候选路线。失败能定位到具体入口—出口转移时记录该转移及方向；无法定位时，仅排除当前候选路线。搜索超时、地图确认失败不能直接证明通道被堵。
4. 对按需验证的结果设置容量上限和版本失效规则，绑定地图、语义、车辆与方向状态。L1 仍输出候选通道序列，不恢复全量离线轨迹库。

交付：逐查询断连与路径质量原因记录、局部精细连接接口、候选路线重选流程、包含成功率与质量的对照结果。

验收：原 20×3 查询继续通过，所有被接受轨迹继续通过原车辆与独立几何检查；增加未用于调参的窄门、急转弯、多入口和首选路线失败但备选可达的场景，单独报告成功分母。区分纯粗图 L2、局部精细辅助、完整精细回退三种完成方式，不能把局部精细连接记为纯粗图成功。六条回退查询逐项报告精细搜索格数、完整回退比例、P50/P95 与状态内存；同时报告配对路径长度、靠右占比、适用段长度及最差查询。停车区额外绕行应减少或得到可复核的约束解释，受控左右偏好继续通过，不能以降低质量换取计时收益。

当前不将形态学重新分区列为前置工作。只有上述定位表明现有子区域或接口切分持续造成错误候选、人工断连或不合理绕行，才增加分区方法对照实验。局部精细连接也不能保证所有窄通道都能用纯粗图完成，目标是减少不必要的完整精细搜索。

## 工作包 2：软参考输入与地图更新开销

1. 定位每次参考代价适配中的重复整图计算；缓存与固定底图相关的中间结果，按地图、参考、偏好和车辆版本绑定。
2. 在能确定影响范围和未变化区域仍有效的前提下，增量处理参考变化；保留实际生效内容校验和修复机制。
3. 逐项定位新组 3/60 次地图重发修复的触发原因，区分发布、消费、版本和内容差异。

交付：细分耗时、受影响区域更新、受限容量缓存、内容一致性测试。

验收：相同静态输入得到相同有效代价内容；左右切换和恢复检查继续通过；报告重复查询时间、适配耗时、重发次数及峰值内存。目标是减少 0.680 秒适配开销和偶发重发成本，收益以同协议配对实测为准。

## 工作包 3：同源动态障碍，先贯通 L2/L3

1. 落实公共障碍事件：世界坐标轮廓、时间戳、来源、置信度、可见范围、占据或显式空闲证据、地图与障碍版本。
2. 同一原始事件分别生成 L3 的 0.05 m 动态障碍和 L2 的 0.15 m 保守表达。保留精细障碍轮廓，动态覆盖与原静态底图分开管理。
3. 分开处理地图更新和重规划触发。对当前实际轨迹及车体扫掠范围受影响的情况触发重新规划；地图或参考版本变化后，重新检查仍未执行的轨迹。
4. 明确清除规则和覆盖归属，不能把遮挡、离开视野或单纯过期解释为障碍已消失；清除单个障碍不能清掉静态墙体或其他障碍的贡献。

交付：公共障碍模块、粗细图增量接口、版本生效确认、动态回放测试。

验收：覆盖新增、移动、显式清除、遮挡、重复与乱序消息、规划期间出现障碍等情形；能追溯 L2/L3 实际使用的版本；旧版本影响到的轨迹不能直接作为有效结果继续使用。先完成回放或仿真验证。

## 工作包 4：L1 通道状态与安全换路

1. 按有向入口—出口关系维护可用、受限、疑似阻塞、确认阻塞和恢复状态，设置持续观测与恢复迟滞。
2. 结合精细通行证据更新状态或代价。一次局部搜索失败不能无条件封闭整个通道；粗图无路先做精细复核。
3. 提前计算备选拓扑路线；路线执行切换须由 L3 从当前真实位姿确认可衔接。已进入窄通道时，验证前进、返回或等待条件。

交付：通道状态机、备选路线生成、当前位姿衔接及切换机制。

验收：覆盖路口前受阻、进入窄通道后受阻、短暂行人经过和障碍移除恢复。近距离减速与停车由执行保护及时响应，规划换路不替代这条响应链路。

## 各阶段共同约束

- 保持原 0.05 m 底图、车辆模型和 Smac 参数，沿用当前语义子区域分解。当前接口状态图为 2,508 个节点、22,024 条可按需展开的有向候选边；2,508 个有向区域接口是另一种统计口径。
- 保留既有 20 条查询，新增困难场景单独报告，不通过替换或删除失败样本提高成功率。
- 分开报告首次、重复、无回退、局部回退和完整回退；同时报告 P50/P95、CPU、RSS/PSS、L3 调用与重试、路径长度和偏好保持情况。
- 每个工作包完成后再比较收益；局部优化不得绕过最终可行性检查。具体时间预算结合首轮定位和目标控制周期确定，不将当前秒级全局规划延迟作为近距离避障响应预算。
